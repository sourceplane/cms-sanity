# apps/web — the blog

A blog whose content lives in Sanity, from Vercel's
[Blog with Sanity CMS](https://github.com/vercel/next.js/tree/canary/examples/cms-sanity)
(MIT), running on Cloudflare Workers + Static Assets:

- Posts, authors and a Settings singleton in a Sanity dataset, read over GROQ
  with `next-sanity` (`sanity/lib/queries.ts`), typed by Sanity TypeGen
  (`sanity.types.ts`, regenerated by `pnpm typegen` and on every build)
- The Sanity Studio at `/studio`, loaded client-side so it ships as static
  assets, with the Presentation tool's live preview through draft mode
  (`/api/draft-mode/enable`), AI Assist presets and Unsplash images
- Every blog page rendered on request against Sanity's API CDN (60 s cache)
- Tailwind 4, Inter, Cloudflare Web Analytics (set `NEXT_PUBLIC_CF_BEACON_TOKEN`)

With no Sanity project id at build time the blog is **unconnected**: it
renders the sample posts in `sanity/lib/sample.ts` under a notice, and
`/studio` says how to connect. The blog's name until its Settings document
gives one is in `app/site.ts`.

```bash
pnpm dev        # typegen + next dev on http://localhost:3000 (the Studio at /studio)
pnpm build      # typegen + next build + opennextjs-cloudflare build → .open-next/
pnpm preview    # wrangler dev over the built Worker
pnpm run setup  # sanity init: pick or create a project and dataset, written to .env.local
```

How it is connected to a Sanity project and deployed — per environment, on
merge to `main` — is the repository's README and `component.yaml` beside
this file.
