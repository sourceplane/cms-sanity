## Departures from the upstream template

### `dynamic = "force-dynamic"` and `fetchCache = "force-no-store"` on `app/(blog)/layout.tsx`

Upstream pre-renders `/` and `/posts/[slug]` and refreshes them with
time-based revalidation (60 s). The Worker serves pre-rendered pages from a
read-only static-assets cache, and a build without a project cannot
pre-render; both routes render on request against Sanity's API CDN (60 s
TTL). `force-no-store` keeps the fetch-level `revalidate: 60` from writing
the read-only data cache on every request.

### `generateStaticParams` removed from `app/(blog)/posts/[slug]/page.tsx`

With the route dynamic there is nothing to enumerate, and Next still runs it
at build — where it reached Sanity with the placeholder project and the
token. Its `postSlugs` query and the `defineQuery` import go with it.

### The Studio loads client-side only

`app/(sanity)/studio/[[...tool]]/page.tsx` renders `studio.tsx` (a client
component that `next/dynamic`-imports `studio-client.tsx` with `ssr:
false`), and `app/(sanity)/layout.tsx` writes out the `metadata` and
`viewport` values instead of re-exporting them from `next-sanity/studio`.
Either import put the `sanity` package into the Worker's server-rendering
chunks (31 MB / 7 MB gzip); the Worker now uploads 7.6 MB / 1.6 MB gzip and
the Studio is 10 MB of static chunks.

### `VisualEditing` from `next-sanity/visual-editing`

next-sanity 13 no longer exports it from the package root.

### Cloudflare Web Analytics instead of `@vercel/speed-insights`

`app/(blog)/analytics.tsx` renders the beacon script when
`NEXT_PUBLIC_CF_BEACON_TOKEN` is set; otherwise nothing.

### Tailwind 4, CSS-first

`app/globals.css` is `@import "tailwindcss"`, `@plugin
"@tailwindcss/typography"`, a `@theme` block with Inter as `--font-sans`,
and Tailwind 3's default border colour in `@layer base`;
`tailwind.config.ts` and `autoprefixer` are gone, `postcss.config.js` runs
`@tailwindcss/postcss`. Forced by `@sanity/ui` 4's cascade-layer stylesheet
(`risks-and-open-questions.md` CS-C).

### Build-time placeholders in the `typegen` and `build` scripts

`NEXT_PUBLIC_SANITY_PROJECT_ID` and `NEXT_PUBLIC_SANITY_DATASET` default to
`placeholder`, `SANITY_API_READ_TOKEN` to `build-placeholder`, when unset:
`sanity/lib/api.ts` and `sanity/lib/token.ts` throw at import and the
Sanity CLI and `next build` both import them. The build makes no Sanity
request (verified with a fetch guard).

### `sanity schema extract --force`

sanity 6 refuses to overwrite the committed `schema.json`. `schema.json`
and `sanity.types.ts` are regenerated by TypeGen 6 (a different format from
the template's committed copies) and committed as generated; `prebuild`
regenerates them, as upstream.

### `.env.local.example` → `.env.example` + `.dev.vars.example`

The project id, dataset and token for `next dev` in one, the token for
`wrangler dev` / `preview` in the other, with the build-time / Worker-secret
split explained in each.

### `next.config.ts`: `output: "standalone"`, `outputFileTracingRoot`

Required by `@opennextjs/cloudflare`; `SC_DISABLE_SPEEDY` kept.

### eslint 9 flat config

`eslint-config-next/core-web-vitals` + `/typescript` through
`defineConfig`, with `@typescript-eslint/no-explicit-any` off by name (the
template was linted against `next/core-web-vitals` alone and types seven
Sanity inputs as `any`); `sanity.types.ts` (the template's `.eslintignore`),
`.next`, `.open-next` and `.wrangler` ignored. One upstream warning is kept
(`rest` unused in `sanity/plugins/settings.tsx`).

### `tsconfig.json`

Next 16 added `.next/dev/types/**/*.ts` to `include` on the first build and
reformatted the file; kept as written by Next.

### `package.json`

`@app/web`, the Workers build pipeline, `preview`, `typecheck`; `dev` is
`next dev -p 3000` (Turbopack is Next 16's default; upstream's `--turbo`
flag is gone); `setup`/`presetup`/`postsetup` as upstream. Versions in the
table below; `@sanity/client` is added explicitly because next-sanity 13
declares it as a peer.

### The unconnected blog (CS3)

Upstream needs a Sanity project before any route renders. A baseline's
product is deployed before its owner has one, so a build with no project id
is the **unconnected blog**: `sanity/lib/api.ts` no longer throws (it exports
`isSanityConfigured`; the dataset defaults to `production`),
`sanity/lib/token.ts` no longer throws (the token is optional),
`sanityFetch` answers from `sanity/lib/sample.ts` (three sample posts typed
by TypeGen's result types) without calling the client, the blog layout
shows a "connect your Sanity project" notice (`app/(blog)/connect-sanity.tsx`),
`/studio` renders a connect page (`app/(sanity)/studio/[[...tool]]/connect.tsx`)
instead of a Studio pointed at no project, and the draft-mode route answers
401 with the reason when there is no project or no token. The `build` script
no longer substitutes placeholders (`typegen` still does, for the Sanity
CLI). A connected blog behaves exactly as before.

### `app/site.ts` — the blog's name (CS3)

`SITE_NAME = "Blog."`, the template's own heading, now lives in one literal
that the baseline's rename rewrites to a product's name; `sanity/lib/demo.ts`
`title` reads it, so it is the fallback heading, the page titles and a new
Settings document's initial title. The sample posts are signed with it.

### The subdomain from the Cloudflare connection (CS-6)

The card's `subdomain` input was typed by hand, though it belongs to the
Cloudflare account the same way its id does and has exactly one right
answer; a wrong value surfaced only after deploy, in the deploy's smoke and
`01-product`'s probes. It now declares `from:
connection.cloudflare.workersSubdomain`, as cirrus-baseline's card does since
baseline-v23: the Cloudflare integration reads the subdomain at connect and on
its hourly health check, the bootstrap door fills the input from the
connection the build is bound to (the one `CLOUDFLARE_ACCOUNT_ID` and the
deploy token come from), the console renders no field for it, and an account
with no workers.dev subdomain is refused at the door. Nothing a blog runs
changes.

- `blueprint.yaml`: the `from:` source and the reason, at the input; key,
  label, pattern, help and example unchanged.
- `testing/manifest.test.sh`: cirrus-baseline's rule, byte for byte — the
  source is accepted, and a `connection.<provider>.…` source whose provider
  `spec.requires.integrations` does not list fails (the card lists
  `cloudflare`).
- `repo-blueprint.yaml`, `BOOTSTRAP.md`, `docs/phases/README.md`: a console or
  `--from bst_…` build reads it from the connection; only a hand-run build
  passes `--set subdomain`. The default is unchanged.

## The domain is set later (CS5, CS-7)

The console asked for the blog's domain, with help text that said it did not
need to exist — and nothing in the build needed one: the blog answers on
workers.dev from its first deploy, it renders no absolute link to itself
(its share-image base URL is the Sanity Settings document's `metadataBase`),
and the one place the repository names the domain is `BASE_DOMAIN` in
`intent.yaml`, for dev, stage and prod. A domain is an owner's step after the
bootstrap (README, "Custom domain"), so the form no longer asks for it.

- `blueprint.yaml` declares no `productdomain` input; the console's Product
  step asks for the blog's name alone.
- `repo-blueprint.yaml`'s `productdomain` is optional, default empty. A
  hand-run build may still pass `--set productdomain=` for a blog that
  already has its domain. Nothing else in the build reads it: no hook, probe
  or `when:` names it, only the `.rebrand/values.json` template, which
  writes `""`.
- `rebrand.mjs` no longer requires it. Empty, it brands the reserved
  placeholder `<reponame>.example.com` (RFC 2606 — never someone else's
  domain) where the domain goes, so setting it later is replacing one
  string; the product README and `ai/context/operations.md` say so.
- `testing/fixtures/acme.json` carries no domain, so the leak gate and the
  offline bootstrap exercise exactly what a console build supplies. Its slug
  ends in the baseline's, so its placeholder, `acme-cms-sanity.example.com`,
  CONTAINS the baseline's own `cms-sanity.example.com`: the engine holds it
  like any value it wrote, and `testing/rebrand.test.sh` pins that (three
  passes, and `--verify` with the values) beside the absent and the empty
  domain. `baseline.yml`'s blueprint read sets no domain.

Nothing that needs a domain was removed — it waits for one.
